# 需求确认单

**REQ-ID**: REQ-v0.1.0-2026-09-10-01
**来源**: 产品规划
**原始描述**:
> 设计文档《基于 A2A 的分布式 Code Agent 协作方案》：
> 「以 orch Agent 为统一入口，把分布在不同机器/环境中的 Code Agent 通过 A2A 注册中心 + MCP 泛型工具组织起来，实现『需求讨论在本地、执行在远端』。」
>
> 用户指令：
> - 「先只处理 opencode codex claudecode 这三个吧 另外三个 记录下来」
> - 「肯定是注册机制呀」
> - 「按照方案B 写方案」
>
> 用户对期望行为的澄清：
> - 「先明确前后端项目的分布机器，然后 orch 任务分配后，再去启动对应项目的 agent。」
> - 「那感觉 也不需要注册机制了 因为 事先已经明确分布情况了」

**要解决什么问题**:
- 当前行为: 项目无实现；前后端项目**分散在不同机器/环境**，orch 既不知道「哪个项目在哪台机器」，也无法按需把某个项目的执行 Agent 拉起来执行。
- 期望行为:
  1. **先显式维护「项目 → 机器/环境」分布**（**事先配置**，非运行时自注册）：明确有哪些前/后端项目、各自运行在哪台机器、以及如何在该机器上启动其对应的 Agent。
  2. **orch 任务分配**：用户任务进来后，orch 判定目标项目。
  3. **按需启动对应项目的 Agent**：定位该项目的机器后，**启动该项目对应的 Agent**（不要求 Agent 常驻）。
  4. Agent 在目标机器的 workspace 执行任务，结果回传 orch。

**影响范围（粗判）**:
- **「项目 → 机器/环境」分布配置**（静态）：项目标识、机器/环境、workspace、Agent 启动方式与访问地址。
- **按需启动/拉起机制**：在目标机器上启动某项目的 Agent（每机常驻启动器 / 远程启动通道），**幂等**（已在运行则复用）。
- MCP 薄桥（泛型工具，读分布配置解析目标）。
- 执行 Agent 包装（**OpenCode / Codex / Claude Code 三端**）：按 `agentKind` 分派无头调用、会话恢复、权限参数。
- **不做**：中心化注册中心 / 自注册 / 服务发现 / TTL 心跳（分布已事先明确）。

**成功标准（用户语言）** — 怎样算"做好了"：
1. 能声明「前端项目 A 在 Windows 机器、后端项目 B 在 Mac 机器」（项目→机器分布可见）。
2. orch 收到任务后能**判定目标项目**，并**启动该项目对应的 Agent**（若未运行）。
3. 任务在**目标机器的 workspace** 真实执行，结果回到 orch。
4. 全程**不需要重启或重连 orch**。

**需求访谈确认的边界（Q1–Q4）**:
- **Q1 启动方式**：每台机器常驻一个**启动器/守护**，由 orch 通知其拉起对应项目的 Agent。
- **Q2 分布维护**：**每台机器自行维护本机项目及其待用 Agent**。
- **Q3 Agent 生命周期**：**用完退出**；但 **Agent 会话需持久化、可继承上下文**。
- **Q4 项目粒度**：**一台机器可挂多个项目**。

**参考/竞品**: `a2a-wrapper`（`a2a-opencode`）、`opencode-a2a`、`a2a-mcp-skillmap`（方案 A 对照）

**优先级**: P0(阻塞发版)
