# machine 配置说明

> **本文件是 machine 单元逐键配置语义的唯一事实源**

## 配置文件

| 配置文件 | 说明 |
| - | - |
| [config.json](config.json) | 实际被读取的配置文件，配置值覆盖配置项默认值 |
| [config.json.default](config.json.default) | 用于记录配置项默认值 |
| [config.json.example](config.json.example) | 配置内容示例，首次使用可复制为同目录下`config.json` |

- 配置文件路径由环境变量 `MACHINE_CONFIG` 指定，缺省 `config/config.json`；两份模板均不参与加载（首次部署自行 `cp config/config.json.example config/config.json`）；启动期读一次 ⇒ 改配置须重启 Launcher。

## 配置说明
### 顶级键层

| 键位 | 缺省 | 合法值域 | 说明 |
| - | - | - | - |
| `machineId` | - | 非空字符串 | 部署机器的身份标识id | 
| `launcher` | - | 对象 | 本地服务信息，详见:[`launcher`键层](#launcher键层) |
| `projects` | - | 数组 | 本地项目信息，详见:[`projects`键层](#projects键层) |

#### `launcher`键层

| 键位 | 缺省 | 合法值域 | 说明 |
| - | - | - | - |
| `port` | - | `1`–`65535` 的整数 | 非整数 / 越界 ⇒ `launcher.port 必须是 1-65535 的整数` | Launcher 本机 HTTP 监听端口 |
| `listenHost` | `0.0.0.0` | 非空字符串 | Launcher 本机 HTTP 监听地址 |
| `idleStopMs` | `300000` | **非负**整数 | 负数 / 非整数 ⇒ `launcher.idleStopMs 必须是非负整数（0 = 禁用空闲回收）` | **按项目**的本地回收判据：该项目无在飞任务 ∧ 静默 ≥ 本值；配置`0`表示禁用空闲回收；单位`ms` |
| `startupCheck` | `true` | 布尔 | 启动自检开关 |
| `startupCheckTimeoutMs` | `120000` | 正整数 | 每项目自检的超时时间；单位`ms` |
| `startupCheckPrompt` | `Reply with exactly: OK` | 非空字符串 | 启动自检**每项目真跑的那 1 条任务**所用的 prompt |
| `shutdownEndpoint` | `false` | 布尔 | 是否注册优雅停止端点 `POST /shutdown`：**仅接受 loopback 来源**。反向代理转发后源地址同样变成 loopback ⇒ **反代必须 deny `/shutdown`**。与 `listenHost=127.0.0.1` 配套使用 |
| `shutdownToken` | 不写 ⇒ **不做 Bearer 校验**（任何 loopback 来源都能停） |  空串 / 非串 ⇒ `launcher.shutdownToken 必须是非空字符串` | 仅当 `shutdownEndpoint === true` 时才有意义：**配了** ⇒ 请求头须逐字等于 `Authorization: Bearer <token>`，否则 401；判序 = **loopback 校验在前、Bearer 在后**。它是**凭据** ⇒ 入库模板永不得含真实值，而模板里想表达「没有 token」只能写空串、空串会撞上面的校验 ⇒ **唯一正确形态 = 整键省略**（不需要 `/shutdown` 时连 `shutdownEndpoint` 一起省略）|
| `bridge` | - | 对象 | orch-bridge地址信息，详见：[`bridge`键层](#bridge键层) | 

##### `bridge`键层

| 键位 | 缺省 | 合法值域 | 说明 |
|---|---|---|---|
| `url` | - | 非空字符串 | orch-bridge的**基址** |
| `token` | - | 非空字符串 | 静态 Bearer token，与`orch-bridge`侧 `machines[].token` 一一对应 |

#### `projects`键层

| 键位 | 缺省 | 合法值域 | 说明 |
|---|---|---|---|
| `projectId` | - | 非空字符串 | 注册时，用于标识project的Id标识;**本机不得重复** |
| `workspace` | - | 非空字符串 | 可为仓内子目录，亦可自成一仓 |
| `agentKind` | - | `opencode` / `codex` / `claude` / `qoder-cn` 四值之一 | 项目使用的agent类型 |
| `a2aPort` | - | `1`–`65535` 的整数 | 该项目的 ACP 桥 A2A Server 监听端口 |
| `risk` | `write` | `read` / `write` / `full` 三值之一 | 任务风险档位（缺省 `write`）。逐 kind 下发：opencode / qoder-cn 直传 `--risk`；codex = `read-only`（另加 `collaboration-mode plan`）/ `agent` / `agent-full-access`；claude = `plan` / `acceptEdits` / `bypassPermissions`（full 档另带 `--session-meta-json`）。三档差别 = 沙箱范围 + 桥对 `session/request_permission` 的应答（read 全拒 / write 取首个 allow / full 优先 allow_always） |
| `repo` | - | 字符串 | 仓库标识，非必填 |
| `agentConfig` | - | 对象 | 项目所用的agent相关配置，详见：[`agentConfig`键层](#agentConfig键层) |

##### `agentConfig`键层

键位口径 = 自消费键顶层平铺（`agentConfig.<kind>` 段已整体退役，段内键写了无效、也不再告警；顶层未知键静默忽略，`roles` 子对象相反、未知键即拒）。保留键：`backendCmd` / `model` / `systemPrompt` / `systemPromptMode` / `timeouts` / `agentCard` / `events` / `mcp` / `roles`（保留只占命名空间、不等于有读点）；新增 `agentKind` 名须先增补保留平铺键名清单。

| 键位 | 缺省 | 合法值域 | 说明 |
| - | - | - | - |
| `backendCmd` | - | 非空字符串（适配器入口文件路径） | 可选覆盖：为空时自动解析`agentKind`的值，按对应默认路径加载（四层链 L0 显式 → L1 `machine/node_modules/<包>` → L2 全局 npm → known 白名单（qoder-cn）→ L3 PATH，命中即停、结果落 `[backend]` 分层日志）；写了即以显式值为准（须存在且是文件，否则该项目不可用）；解析不到 ⇒ 该项目不可用，机器级故障只有全部项目不可用 |
| `model` | - | 非空字符串 | agent的modelId，经适配器原样透传桥 `--model`：machine 侧不校验、不映射，缺键 / 空串 / 非字符串 ⇒ 后端用自身默认；会话建立后发一次 `session/set_config_option {configId:"model"}`。可填值清单参考 [model-catalog.json](model-catalog.json)。`effort` / `reasoning_effort` / `mode` 不接线 |
| `systemPrompt` | - | 非空字符串 | 自定义系统提示词，经桥 `--system-prompt` 透传 |
| `systemPromptMode` | `append` | `append` / `replace` | 与 `systemPrompt` 配套，经桥 `--system-prompt-mode` 透传 |
| `sessionTimeoutMs` | `600000` | 正整数，≤ `600000`（10 min） | 会话窗，agent单次会话的时长上限；派发总框按项目派生（`dispatchBudgetMs` = 生效窗 + 结构余量 300000 + min(续跑余量, 生效窗)，未配窗时 = 900000）。生效值随 `config-snapshot` 播报落 launcher.log |
| `continueMarginMs` | `0` | 非负整数，≤ 本项目生效会话窗（`sessionTimeoutMs` ?? 600000） | 续跑余量：满窗后允许续跑一轮的额外额度，`0` = 不续跑；与配没配 `sessionTimeoutMs` 无关 |
| `sessionRetentionDays` | `7` | 正整数 | SessionMap 条目 TTL 天数 |
| `sessionRetentionMax` | `500` | 正整数 | 单项目映射条数上限（LRU） |
| `maxConcurrentWrites` | `1` | 正整数 | 同 project 写档并发上限 |
| `maxConcurrentReads` | `1` | 正整数 | 同 project 读档并发上限，配 ≥2 才真并行只读 |
| `roles` | - | 嵌套对象 | 按任务角色配置模型，详见 [`roles`键层](#roles键层) |

###### `roles`键层

> {<roleName>: {key: value}}，其中rolename仅支持四个值：`unit_agent` / `product_manager` / `project_manager` / `dev_manager`

| 键位 | 缺省 | 合法值域 | 说明 |
| - | - | - | - |
| `model` | 不写 ⇒ 回落 `agentConfig.model` | 非空字符串 | 该职责位本轮的模型，取值形态同顶层 `model` |
| `systemPrompt` | 不写 ⇒ 回落 `agentConfig.systemPrompt` | 非空字符串 | 该职责位的系统提示词 |
| `systemPromptMode` | 不写 ⇒ 回落 `agentConfig.systemPromptMode` | `append` / `replace` | 与 `systemPrompt` 配套 |
| `risk` | 不写 ⇒ 回落项目生效 risk | `read` / `write` / `full`，且不得高于项目生效 risk（rank `read` < `write` < `full`） | 该职责位的权限档，档位映射同 `projects[].risk` |
