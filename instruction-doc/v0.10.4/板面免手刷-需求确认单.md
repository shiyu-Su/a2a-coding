## 要解决什么问题

> 本节确认点 =「我理解你要解决的是不是这个问题」——确认的是问题，不是方案。

- **当前行为**：
  - 板五类页面（门户 / 排期页 / 任务页 / 需求详情整页 / 管理页）一律**纯 SSR + 手动重载**，无任何页级自动刷新（board `src/web/layout.ts:12-13` 口径钉）；全站唯一自动更新 = 需求详情**浮层动作区**提交后的有界进度轮询（件B，v0.9.5）。
  - 任务页「快捷项目选项」是**纯 `<a href>` 默认导航**（board `src/web/views.ts:957-967`），点击整页跳转；该页**零业务脚本**（`src/server.ts:1357-1367, 1399-1405` 两档均不传 `extraScripts`）。
  - 板 README.md:233 **自己登记过这个缺口**：「不做 meta-refresh / 自动刷新……登记遗留项」⇒ 诉求①属「遗留项转正」。
- **期望行为**：
  - ① 数据变更（orch agent 新增需求卡 / 任务状态变更）**自动反映到页面**，不经手动刷新。
  - ② 任务页点快捷项目选项，**只更新结果内容区**，不整页跳转。

## 关键核实结论

### board 侧（inquiry `3fe77180`，board 产品经理）

1. **页面刷新现状**：五类页面全部「手动重载」；排期页拖卡成功后 `location.reload()`；任务页连「拖拽脚本」都没有。README.md:233 拒自动刷新的两条既有理由 = ① 自动刷新不在脚本闭集内 ② 与 ~30s 调度拍错拍。
2. **★既有局部更新机制可复用（不得另起第二套）**：件B 机制 = `setTimeout` 自递归链（非 `setInterval`、非 SSE/WebSocket，全站 `EventSource`/`WebSocket` 零命中）+ **fetch 同源整页 → DOMParser 摘 `<main>` → 换入容器**（`src/web/layout.ts:335-397`），周期 5s、上限 240 tick、收口即停、**零新端点**。但它的**唯一调用点**是浮层 `postForm` 成功分支 ⇒ 「**进页即轮**」这条链需新增半边。排期页卡片 `<a href^="/features/">` 已有 click 委托 → fetch → `swapPage` 先例（`src/web/layout.ts:461-465`）⇒ 任务页局部化的现成形态就在那枚脚本里。
3. **两条硬约束**：① **内联脚本闭集 = 七元、每枚恰好 1 处**（`test/n3-regression-anchors.test.mjs:509-520, 554`），新机制合法形态只有两条 = **扩第八枚**（翻新 N3-⑦/⑧ 锚）或**在既有枚体内扩**（有先例）；② **CSP 不必放宽**（`connect-src 'self'` 已放行同源 fetch）。
4. **快捷项整页跳转根因** = 「缺局部刷新脚本」（不是 submit 未 preventDefault、不是服务端重定向）；**服务端已具备支撑**：`GET /tasks?project=X` 已返回 200 任务表（深链 C1 例外存活）⇒ **读面零改动**，只需前端拦截 + fetch + swap。⚠ 同页另有**三条整页动线**（过滤表单 GET 提交 / 「不带过滤重查」a / 「换项目」a）——只做 chips 会留下不一致，是否一并局部化须裁。
5. **URL 承载**：参数已完整承载筛选（`project`/`state`/`limit`）；全站 `pushState`/`replaceState` **零先例**，但可行且降级面安全（后退走整页导航 = 同 URL 同读面，可接受）；chips 当前态 `.on` 由服务端渲 ⇒ 局部更新应**整块换掉含 chips 的过滤卡 + 结果卡**（照 `swapPage` 口径），不由脚本自改 class。
6. **board 表态：接，评估合理**。两诉求全落 board 只读投影面：不改写面白名单、不改状态机、不新增存储、不放宽 CSP。

### orch 侧（inquiry `a7047d47`，orch 产品经理）

7. **v0.8.3 push 退役动机 = 「附加链清理」（架构收尾 + 死码拆除），既非不可靠、也非负载** —— 被退链方向 = **worker→orch**，与「orch→板」推送**方向相反**；板要的那条推送在本仓**从未有过、从未被裁决**。⇒ v0.8.3 **不能引用为支持或反对 SSE 的依据**；要走 SSE/长连 = 新立跨单元通知协议语义，须独立评估。
8. **「引擎主动通知板」在不扩协议的前提下不可行**：3300 只读面仅 9 条 GET 路由、无 wait/subscribe/SSE 路径（非 GET 一律 405）；带挂起语义的 `a2a_wait`（≈25s 上限）只在 8787 `POST /mcp` 面、浏览器用不了。⇒ **只能板侧轮询**。`/api/events` 是无状态游标增量快照轮询（可用），但**绝不改走会推进宿主收件箱游标的那条路**（机制上安全，3300 面不碰游标）。
9. **负载粗判**：读面全部**每请求现算、零缓存**（`cache-control: no-store`）、单例同步 SQLite 连接（多页签请求在进程内排队）。**30s × 1~5 页签无虞；15s 安全**（= orch 自身 `WEB_MIN_REFRESH_MS` 文档化下限）；**5s 档浪费可容忍**。⚠ 两个压力点：`/api/versions`（8787）逐行 release-gate join = N+1、最重；**`/api/tasks` 每次 GET 带 `pruneTasks()` 写库** ⇒ **任务页轮询周期建议 ≥15s**（否则「只读轮询驱动周期性写」）。
10. **orch 表态：接** —— 轮询档 **orch 零代码改动**可承接；SSE/长连档 = 跨单元协议面，**本版不走**（board+orch 两单元一致）。

## 成功标准（用户语言）

1. 排期页开着不动，orch agent 新建一张需求卡 / 某需求状态变化 ⇒ **N 秒内**入版需求清单与其状态自己更新，不用刷新。
2. 需求详情页开着等任务跑 ⇒ 页内任务状态（执行明细 / 依赖图状态 / 步条）**N 秒内**跟随。
3. 自动更新**不打断人**：正在填的表单、已展开的折叠、进行中的拖拽不被重置/顶掉。
4. 任务页点快捷项目选项 ⇒ **页面不整页跳转**，任务状态就地更新为所选项目。
5. 地址栏跟着筛选走（若 ⑥ 裁 pushState），刷新/分享后落同一筛选态。
