## §1 背景与评估

- **目标**：管理页两栏项目池加一枚「⟳ 刷新项目池」按钮，点击后重取最新快照、更新左栏「未加入组的项目」；**实现档位 = D 零脚本档**（原生 GET 表单回本页，整页重载重跑四路读）。
- **评估结论：合理**。零引擎/协议/数据面改动、零新端点、零脚本（八元闭集不变）、既有锚预计零翻案；board 单侧闭合；与乙卡 858e9e46（管理页属其显式排除页，本卡不进其刷新面）零边界冲突。依赖：实现须待乙卡收口成新 HEAD（行号基线）；本卡是甲卡 4ca97bcd ⑦「仅保留拖拽」的前置。
- 「在线」语义 = 心跳登记态（非实时探测，离线机项目照常入池）——用户已知情接受；池面不显在线徽标（池-⑯ 带牙钉不破）。

## §2 方案设计

1. **按钮形态（D 档定案）**：`<form method="get" action="/org/<名>/manage" class="m-refresh"><button type="submit">⟳ 刷新项目池</button></form>`。无具名控件 ⇒ 提交 URL = action 本身，**零 query、连 `?` 都不追加**，与直接重开本页逐字同 URL（附带口径 (1)，研发经理确认；不加 `?refresh=1` 标记——服务端行为完全等价，零收益）。★R1
2. **落点 = 甲：卡体首行**（两栏容器 `m-pool` 之上、三档统一前置）。★R1 **落点层硬伤（推翻 Step 0 「卡头 meta 行旁」预设）**：`cardShell` 把 meta 渲进 `<p class="b-card-h">`，HTML 解析器在 `<p>` 内遇 `<form>` 会先关闭该 `<p>` ⇒ form 被抛出卡头、卡头 DOM 与服务端字符串分叉——锚绿而真机排版坏的静默错位。故 form 只能落卡体；不改 `cardShell`（为落点改 meta 容器会牵动全站卡头，弃）。
3. **三档统一在场**（附带口径 (2)）：正常 / 未查询 / 不可用 三档 `cardShell` 的 bodyHtml 各前置同一表单（单点变量 `const refresh = renderPoolRefreshForm(org)`）——降级档「刷新本页重查」的落点；桥宕机时点击仍整页重载、如实回「不可用」不炸 502。
4. **无 JS 天然可用、无死钮**：原生 submit ⇒ 导航，不需要 `hidden` 缺省（与乙卡 ⟳ 钮的 JS 依赖不同源）；`SUBMIT_GUARD_SCRIPT` 对 `method!=="post"` 直接放行、`PAGE_LIVE_SCRIPT` 在零 `data-live` 页整枚不启动 ⇒ JS 在场也不劫持。
5. **观测时刻与两栏同拍**：一次点击 = 一次 GET = 四路 `Promise.all` 并读在同一次渲染内完成；`sendPage` 恒发 `cache-control: no-store` ⇒ 重载必然回到服务端重读（D 档成立前提）。
6. **类名独立**：`m-refresh`，**不复用** `.live-now` / `a.fl`（后者是第八枚 click 委托选择器 `.b-card a.fl` 的命名空间，误用即接进第八枚委托）；零新色值（全局 button 样式已够看，B3 CSS 可选一行、建议零 CSS）。
7. **新增 views.ts 模块私有函数** `renderPoolRefreshForm(org)`，不外抛新导出。
