## 关键核实结论（board `05b516d6` 产品经理 / `bae9855e` 研发经理）

1. **件一根因（被核实收窄纠正）**：不是「角标带渲染在节点下方」，而是**没有跨管道角标时 `.dg-deps` 外壳压根不渲** —— `renderPipeCell` 的角标带是条件性出参（`marks !== ""` 才出），而 `crossIn` 只登记**两端异 project 的边** ⇒ 单 project DAG 上外壳恒缺席 ⇒ chip 顶到 cell 顶（少占 14px）⇒ 几何模型按「角标带恒预留」算出的端点整体低 **`DG_BADGE_H` = 14px**，恰好落在节点底边框。宿主实页实测逐字对上：端点 y = 40 / 92，chip 盒 `[x, 12, 74, 28]`、边框线中点应为 26 / 78。
2. **件一的结构性盲区**：单元测试 I2「端点恒等」由**同一个 `PipeGrid` 模型**重算端点 ⇒ **自洽性断言（模型自证模型）**，结构上抓不到「模型 ↔ 渲染」漂移 —— 这正是 62 条全绿却真机不合格的原因。
3. **件二非缩放**：实页全祖先链 `transform` / `zoom` / `scale` 零命中、`devicePixelRatio = 1`、`visualViewport.scale = 1`；chip 实测 74×28、字号 12px、线宽 1.5px，与原型 C 同档 ⇒ **节点盒没被放大，被放大的是间距**（列距 170 vs 原型 130、行距 52 vs 原型 46）。原型 C 的连线 `y = 44 = 30 + 14` ⇒ 原型里端点就是 chip 中线，**与件一互证「模型侧没错、渲染侧丢了 14」**。
4. **两件可一次改完、单节点可容纳**：只碰 `src/graph-view.ts`（常量块 + `renderPipeCell` + 两处注释）与 `test/graph-view.test.mjs`（翻 4 · 增 2 · 删 0）；按 (A) **CSS 零改动** ⇒ `layout.ts` 不碰、`live-refresh` / `n3-regression-anchors` / `web.test` 三条禁改面零触达。其余测试文件全仓 grep `dg-cell|dg-deps|DG_COL_GAP|DG_ROW_GAP|DG_BADGE` **零命中** ⇒ 翻案面闭合在本文件。
5. **幅度的物理下限**：`DG_COL_GAP_MIN` 不得 < 45（否则同通道 λ/μ 可能 `tx ≥ tx2` ⇒「水平段不自交」判红）；取 56 时 n≥1 的通道由 `gapW` 公式 floor 58 接管 ⇒ 安全。
