## §1 背景与评估

**目标**：需求详情页「依赖图」按**真实依赖边**绘制 —— 分支处**分叉**、汇合处**合并**；并行节点呈并列，不再被 `→` 串成一条线。

**现状 = 病态**：`renderPipeline()`（`src/graph-view.ts:468`）把同 project 的 chip 用 `join('<span class="dg-arrow">→</span>')` 拼成一条线 —— **箭头 = 相邻位置产物**，与 `graph.edges` 零交集；管道由 `groupPipelines()`（`:282-301`）按 `projectId` 分组、组内按 `queuedAt` 升序，同样与依赖无关。

**实测证据**（样本 `076bbb84`，7 节点 / 10 条真依赖边；board Step 0 复核）：6 枚箭头里 **2 枚是假边**；10 条真边里 **6 条完全未被表达**；标题三元计数（`:547`）口径本身正确、**数据面零缺陷**。

**评估结论：合理，但形态必须专设。** 用户三条硬判据（§2.6）合起来**排掉「A 点连一条贝塞尔到 B 点」**，走线必须在预留通道里做 ⇒ 定稿形态 = **固定网格 + 通道走线 + 内联 SVG**（§2.2 α）。代价 = 须主动**推翻两条既有负钉**（这恰是本需求的本体）。board 单侧闭环：零引擎 / 零协议 / 零数据面 / 零新脚本。

### §2.4 分层与通道走线（纯函数，无 DOM / 无度量）

**① 分层（C3 后 = 全图）**：`layerOfGraph(graph.nodes, ordinals, graph.edges)` —— **全图**最长路径分层（Kahn + 就绪集按 `taskOrdinalMap` 号序取，确定性；含**跨 project 边** ⇒ 「只依赖他管道」的节点**不再被压回 layer 0**）。输入 `edges` 已被 `buildTaskGraph()` 滤环 + 去悬空 ⇒ 恒为 DAG，**不重复防御**。

**② 密列压缩**：`compressPipeLayers(pipe, layerOfGraph)` —— 每管道把全局层号压成**密列**（该管道无节点的中间列不占位）。给出的可证性质：**管道网格每一列非空** ⇒「画线边列差 ≥2 ⇔ 中间必有本管道节点 ⇔ 必须走通道带」。相邻性定义随之改为 **`localCol` 差**：=1 ⇒ 相邻弧；≥2 ⇒ 三段通道带路径。

**③ 网格**：`pipeGridLayout(...)` → `cols / cellOf / colX / gapW / rowY / width / height / busLanes`；列内按**号序**（待裁②），`row` = 列内下标 ⇒ 同列格位两两不同；`gapW[c] = max(DG_COL_GAP_MIN, DG_LANE_MIN*2 + lanesInGap(c)*DG_LANE_PITCH)`（lane 数由走线预算回灌，**一次收敛不迭代**）。

> **N2 实落口径（v4 同步 · 见 §5 偏离汇总 D-2）**：签名 `pipeGridLayout(pipe, columns, ordinals, budget)`；**lane 数是入参不是产出**（`budget.gapLanes[c]` / `budget.busLaneCount`，缺省 0 ⇒ 未回灌时 `gapW` 恒取下界 96）；出参除规格件外**另给取数面**（`cols/rows/colX/rowY/gapW/cellOf/busBandTop/lanes/busLanes`），供走线与 I2 重算不必二次派生；`lanes[c]` = 通道内各 lane 的 **x 线**（`colX[c]+NODE_W+DG_LANE_MIN+i*DG_LANE_PITCH`，与 ④ 的 `tx` 同式）、`busLanes` = 带内各 lane 的 **y 线**，**首线取 `busBandTop + ⌊DG_BUS_PITCH/2⌋`**（② 的 `yb = 通道带底 + busLane*DG_BUS_PITCH` 由此具体化，本处为唯一口径）；I4 两式由构造取**等号**（`width = 最右 chip 右缘 + max(DG_PAD_R, DG_BADGE_MAX_W)`、`height = max(最后一格底缘, 通道带底) + DG_PAD_B`）；「每列非空」在本函数内**结构性兜底**（入参列号按出现值升序重编号 —— 对 `compressPipeLayers` 的密列出参恒等、不改结果）；`DG_CELL_H`（= `BADGE_H + NODE_H`）留作文件内**私有**常量，导出面严格等于本表点名的 12 枚 `DG_*`。

**④ 走线**：`routeIntraEdges(...)` →
- **相邻边**：一枚三次贝塞尔 `M x0,y0 C x0+K,y0  x1−K,y1  x1,y1`（两端切线**水平** ⇒ 与判据 1 的边框中点吻合）；`K = clamp((x1−x0)/3, 6, DG_ARC_K_MAX)` ⇒ 同起点多条边**天然不同 K**（立即分岔，不共首段）。x 跨度 ⊆ 单一列间通道（凸包性质）⇒ **结构上不可能穿节点**。
- **长边（列差 ≥2）**三段全在预留通道内：① 下降弧 `P0 → Q1=(tx, yb)`，`tx = x0 + DG_LANE_MIN + λ*DG_LANE_PITCH`（λ = 该边在通道 `G_c` 的**独占 lane**）；② 通道带水平段 `Q1 → Q2`（`yb = 通道带底 + busLane*DG_BUS_PITCH`）；③ 上升弧 `Q2 → P1`（`tx2 = x1 − DG_LANE_MIN − μ*DG_LANE_PITCH`）。①③ 与 ② 在 Q1/Q2 处**切线同为水平 ⇒ C¹ 连续**（无硬角）。
- **通道分配（判据 2 的可证形式）**：`busLane` 按（源号序, 目标号序）定序贪心，复用**当且仅当 x 区间两两不交**（区间装箱）；`λ/μ` 同通道**单射独占**，仅当两条边在该通道的 **y 区间不交**时允许复用。

> **λ / μ 的两侧口径（N3 实落 · 见 §5 D-3）**：`λ` 自**源通道左缘**起算（即 `grid.lanes[]` 的 x 线口径），`μ` 自**目标 chip 左缘反向**起算（`tx2 = x1 − DG_LANE_MIN − μ*DG_LANE_PITCH`）。`gapW` 被预算抬高时二者**镜像重合**（λ 占下标 `0..nλ-1`、μ 占 `nλ..n-1`，结构上不碰撞）；但 `gapW` 恒取下界 96 的样本上，`μ` 落在通道内而**不命中** `grid.lanes[]` —— 这是两式各自定义的必然结果、**不是缺陷**，故机器判据只对 **λ 侧**断言「命中 `lanes`」、对 **μ 侧**断言「在通道内 + lane 号两两不同」。

### §2.5 四条不变式 = 三条硬判据的机器形式

| 不变式 | 陈述 | 钉住 |
|---|---|---|
| **I1 通道包含** | 每段（弧取 4 控制点 / 线取 2 端点）的 bbox ∩ **非本边两端** chip 盒**内部** = ∅；与本边两端只许边界接触 | **判据 3**（bbox ⊇ 凸包 ⊇ 曲线 ⇒ 充分条件，只误严不误漏）。夹具：6 层链、长边跨 3 列、**单行 R=1 全长边**、宽 fan-in |
| **I2 端点恒等** | 解析 `d` 首点 === 源 cell 右缘中点、末点 === 目标 cell 左缘中点（由同一 `PipeGrid` **重算**，非硬编码） | **判据 1**（逐边遍历 + 空转守卫） |
| **I3 不共段** | 结构面：λ/μ 单射（同 y 区间）、busLane 内 x 区间两两不交；兜底面：每段采 24 点，两边采样点集中「距离 < 1.5px 的点对 ≥2」⇒ 判红 | **判据 2**（§2.6 口径） |
| **I4 内容包含** | `width ≥ 最右 cell 右缘 + DG_BADGE_MAX_W` ∧ `height ≥ 通道带底 + PAD_B` | 防 `overflow` 双向裁切 |

### §2.6 判据 2 的**定义式**（用户 2026-10-12 裁定）

> **「允许交叉；只禁叠线 —— 共端点不算重叠、共段才算重叠、孤立交点允许。」**

⇒ **不上减交叉**（不引入重心/顺序优化），**不升档、不重走 Step 0/1**。本定义式同时作为 I3 断言的**注释锚**，防后人把它当缺陷「顺手加固」。

> **反例的成立前提（N4 原地重派收口时并入 I3 断言注释，见 §5 D-4）** —— 三条，缺一即成**空转**或**误判**：
> ① 兜底面（每段采 24 点）的「叠线反例」须 **`μ` 同值 ∧ `yb` 同值**（水平段同线）才成立；**只改 `μ`**（`yb` 不同 ⇒ 两弧仅共 x、不共段）⇒ 兜底面**必须放行** —— 该负钉钉的就是「只禁叠线、不把共通道当叠线」。
> ② 「同源通道 ∧ y 区间相交」的长边对**不是所有夹具都有载重**：`busReuse` 夹具按设计两条长边**源通道各异且 x 分离** ⇒ 该计数恒 0；夹具的真实载重改钉 `busPairs` / `reusedLanes`。
> ③ I1 的「抬 y 越缘」反例须**断在最后一行**的 cell 上（`row === rows-1`），否则反例 box 落进上一行的 y 带、与贴边反例互不相交 ⇒ 两条同时空转。

### §6.1 增补节（增补 Feature `d69f494d-07c5-470e-bf3f-ca0ff72ba749`，挂本主需求）

**根因（两件同源；件一被 Step 0 收窄纠正）**
- **件一**：几何模型假设 chip 占 `[ROW_Y + DG_BADGE_H, … + DG_NODE_H]`（角标带在节点**之上**），而 `renderPipeCell` 的 `<span class="dg-deps">` **外壳是条件性的**（`marks !== ""` 才出）；`crossIn` 只登记**两端异 project 的边** ⇒ **单 project DAG 上外壳恒缺席** ⇒ chip 顶 = cell 顶 ⇒ **端点整体低 14px（= `DG_BADGE_H`），落在节点底边框上**。宿主实页实测：端点 y = 40 / 92，chip 盒 `[x, 12, 74, 28]`、边框线中点应为 26 / 78。**多 project DAG 上会混排**（有带的 cell 正确、没带的偏 14），现无夹具覆盖。

**方案（件一取 (A)；件二取 b2′）**
