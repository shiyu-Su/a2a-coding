## 关键核实结论（board 产品经理 `ea17066d`）

1. **现状（A 组，四条属实）**：见上「当前行为」（行数实测 2558，题面「约 2200」偏低，不影响结论）。
   - 题面外补充的既有约束：graph 锚带 `data-live-lock`（`views.ts:827`）⇒ **页面任一非 pipe `details` 展开 ⇒ 整页所有 lock 锚跳拍**（`layout.ts:1027-1029`）；`holdAnchor` 豁免类**只有 `pipe`**（`layout.ts:1036`）。⇒ **图锚的免手刷吊在「SSR + `data-live` 逐拍换块 + `holdAnchor`」三条硬约束上。**
2. **技术可行性假设（B 组 · 头号结论）**：**「React Flow + ELK.js 客户端整体解」与 board 三条既有硬约束存在架构冲突**（board = 纯模板字符串 SSR + tsc，无 React、无打包器、运行时零依赖）。三条路径粗判：① 局部水合 —— 可行但中大，且与「逐拍换 children」相冲（React 根每 15s 连根替换，须改免手刷面纪律）；② 换块时 React 重挂 —— **基本不成立**（ELK 异步布局 ⇒ 每拍重排闪烁）；③ 整页转 SPA —— 可行但最大（推翻 `views.ts` 2972 行 / `layout.ts` 1728 行 / 八枚脚本闭集）。
   - **更简的第四条路径（board 主动提出）**：**只引入 ELK.js、在 Node 服务端跑 layered + 正交布局，不引入 React Flow** —— ELK 是纯 JS、可在 Node 直接运行 ⇒ SSR 直出「预算好的坐标 + 正交折线」，渲染形态**原样保留**，三条硬约束**零触碰**、水合问题整个消失。React Flow 的增量价值 = 客户端交互（pan/zoom/拖拽），而本依赖图是**只读展示面、本需求未要求交互**。
   - 依赖与离线（无 CDN）：ELK 服务端路 = 加 `dependencies: elkjs` 一枚、tsc 产物直接 `import`、**不需要构建链**；React Flow 路 = vendor React + react-dom + @xyflow/react（先例：mermaid.min.js 白名单 vendored），或引入 esbuild/vite 新构建步骤。
   - 语义映射（B3）：管道框 = ELK **compound node**、跨框边 = 全局正交路由、六态配色 / 图例 7 枚 = 渲染侧 CSS（渲染形态不变则天然保留）；**「连线两端落边框线中点」需显式用 ELK `ports` 钉死**（ELK 自由选锚不保证中点 ⇒ 属 Step 1 配置核实项）。
3. **影响范围（C 组）**：仍 **board 单单元**（纯展示面；数据源 features/tasks 查询零改动，不牵 orch / machine / 协议）。
   - 翻案面：`test/graph-view.test.mjs` 实测 **150 枚 `test()`**（5743 行；题面「约 119」偏小）。走线 / 几何类估 **60–80 枚**须翻案 —— 其中**大半可降为行为级锚**（「无交叉」「无共线重叠」「正交」是与引擎无关的机械谓据）；结构锚（零 script / 单枚 svg / 类名闭集 / 接点中点）+ 六态 / 图例 / 免手刷锚在 **ELK 路下基本全保**、React Flow 路下大面积翻。根列车 `test-v0.10.6-dep-graph.js` 共 14 枚锚，其中源码符号锚（`DG_EDGE_CROSS_CLS` / `layerCrossApproach` / `DG_APPROACH_*`）随走线函数退役须改行为断言或随版退役。
   - 体量：**ELK 服务端路 ≈ src 1200–1800 行 + 测试 3000–5000 行 = 中体量单主轨**；**React Flow 路 ≈ src 2500+ 行 + 测试近全翻 + 新构建链 = 大体量**。
4. **需求合理性（D）**：board **接** —— 三条不满为真实观感缺陷，且逐条落在既有锚许可口径内 ⇒ 锚面无法再收紧、手写走线已到收益递减点，换成熟布局引擎方向合理。
