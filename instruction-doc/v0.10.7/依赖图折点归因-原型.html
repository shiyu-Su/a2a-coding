归因结论

  • 核验：直接从真板页面 GET /features/f55d46af-… 的 12 条 path.dg-edge 提取折点 = 28（10×HVH + 2×HVHVH，端点偏差全 0），与本原型 (a) 的离线复现逐字一致（同段序、同坐标）。
  • 主因①（层方向与端口约束打架）= 24/28 折点（86%）：direction=DOWN 把层竖排，端口又把每条边钉成「源右缘出 → 目标左缘进」，于是每条链边只能走「右 → 下 → 右」的 HVH，每边固定 2 个折点、12 条边 0 条纯直线（12×2=24）。这不是 ELK 算法差，是这两个选项互相矛盾。
  • 次因②（同层两支的错位）= 4/28 折点（14%）：#6 / #7 同层（一支分两支），在 DOWN 模式下同层两支横排 —— #7 落到 x=608，而它的后继 #8 在 x=598 / y=335，即目标在源的左下方，于是 #5→#7、#7→#8 两条边走 HVHVH（各 4 折，比基线多 2）。变体 (b) 里残留的 4 折是同一因的另一面：RIGHT 模式下同层两支纵排，#6 落到第二行（y=95），与它相连的两条边各需 1 次 HVH。
  • ③跨 project 容器 = 本例 0 折：12 个节点全在同一 lane，crossEdges=0，本条不参与本例。
  • ④端口约束本身不额外加折：变体 (c) 去掉端口后折点 28→4，但省折的实质是「不再强制右出左进」（端点漂到上缘/下缘，偏差 39.6–51.3px，右出左进命中 0/12）—— 端口对折点的影响始终经由「方向」这一环起作用。
  • edgeRouting=POLYLINE 无效：变体 (d) 与现状逐字相同（28 折、段序同为 HVH）—— 端口钉死两端后，polyline 也只是把线画成折线，省不出折点。
  • 回答用户的判断（问题 4）：把层方向改为 RIGHT（= 用户说的「平铺」：层从左往右、任务躺在同一水平线），同时保留「右缘出 / 左缘进」端口约束与正交走线 —— 折点 28 → 4，纯直线边 0 → 10/12，右出左进仍 12/12，画布 1068×575 → 1068×143。但 0 折点做不到：本图有一处「分叉 + 汇合」（#5 → {#6,#7} → #8），同一水平基线上两支必有一支脱离主干行，这两条边各需 1 次 Z（2 折）。0 折点仅当依赖图为纯链（无分叉/汇合）时可达。
