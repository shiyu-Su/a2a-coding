## §1 背景与评估

**目标**：

1. 排期页拖需求卡时，指针落在目标版本框**任意可见位置**（列头 / 卡片上 / 框内空白 / 空框）都能放入。
2. 拖动经过目标版本框时**整框持续、清晰的高亮**（不再在卡片上消失）。
3. 不破坏既有行为（闸锁卡拖不起、锁定态 409、免手刷机制）。

**需求评估结论：合理**。经 board 单侧代码核对，两条根因成立、边界方向正确、无架构冲突、**无跨单元契约影响、无协议升版**（本需求不改数据面 / 引擎 / 协议 ⇒ board 单独走版，不触发单元同升组，flow 规范四戳本版预计零触达）。

**两条根因**（board Step 0 只读核实，`8c04e564`）：

- **① 几何**：`.kanban{align-items:flex-start}`（`layout.ts:1501`）+ `#schedule-board > .kcol` 只有 `max-height` 无下界（`1510`）⇒ 短列 / 空列（台账独有版本 `byVersion.set(v, [])`，`views.ts:2141`，置位列仅含 `<h3>` ≈ 40px）下方空白**不属于该列**，命中函数 `colOf` 返回 `null` ⇒ 放不进。
- **② 高亮**：`colOf` 只认 `data-version`，卡片自身也带 `data-version`（`views.ts:2174`）⇒ 指针在卡上时命中**卡片**（CSS 全仓**从不存在** `.kcard.dragover` 规则），且进子元素触发父 `dragleave`（`811-814`）⇒ 整列高亮消失（功能上其实仍能落成）。用户实测补充「只有和版本列标题重叠时才显示外虚线框」即此。

## §2 方案设计

> 定稿口径 = B1′–B5′（R1 初版边界 → R2 收敛修订版，board 逐项接受）。全部落在 `board/src/web/layout.ts`（`views.ts` 零改动）。

**B1′ 落点与高亮单点归列**（合并原 B1 + B3 + board S2/S3 + R2-新1 复位）

- `colOf`（`layout.ts:758-765`）判据由「首个带 `data-version` 的祖先」改为「首个 `classList.contains("kcol")` 的祖先」（保留 `nodeType===1` 与 `el !== board` 上溯边界）。列上恒有 `data-version` ⇒ 下游 `col.getAttribute("data-version")`（`824`）与同版早退零请求（`825`）语义**零变化**。
- `dragover`（`804-810`）加**单列跟踪**：`over !== col` 时先摘旧列再挂新列（消除快速横扫多列时多列同时冒虚线）。插入点须避开 `n3:469` 钉的 `preventDefault();` 与 `dropEffect = "move";` 两行相邻性。
- `dragleave`（`811-814`）加 `e.relatedTarget` 守卫：仍在同列内（进子元素）⇒ **不摘**高亮；`relatedTarget` 为 null ⇒ 视为离列、照摘（兜底方向不得反写为「取不到就不摘」，否则高亮粘死）。
- **R2-新1（必须补）**：单列跟踪的 `over` 须随 `drop` / `dragend` **双复位为 `null`** —— `drop` 内摘类处（`819`）紧随 `over = null;`、`dragend` 清类循环之后（`828-833`）`over = null;`。**不复位 ⇒ 第二次在同一列拖拽时 `over === col` 走跳过分支 ⇒ 整根虚线从此不出现**（409 拒后不 reload、用户立刻重试的时序最容易命中）。
- `JSDoc`（`743-744`）**同轮改写**（原文写「以属性存在而非 class 判定」，与 B1′ 正面相反）。

**B2′ 列高（档 B 定稿 · 用户 2026-10-13 裁「不接受各列等高，保持列高不齐」）**

- 只给 `#schedule-board > .kcol` 合入 **`min-height: 160px`**，**不加 `align-items: stretch`**（保持列高不齐）。
- **取值理由（Step 2 研发经理定稿）**：`min-height` 越大越接近「变相等高」（如 `calc(100vh - 200px)` ≈ 700px ⇒ 列高差 ≤ 80px），与用户裁决**正面冲突** ⇒ 取 `160px`：只把空占位列 / 空池列（`views.ts:2141`，仅含 `<h3>` ≈ 40px）撑成一个可见可瞄的框；带 2–3 张卡的列本就 ≥ 200px、不受该值约束 ⇒ **列高真不齐**。
- **作用域**：仅 `#schedule-board > .kcol`；不动全局 `.kanban`（保 `#org-portal` 版式）。
- **已知残余（档 B 固有，登记 §6）**：「高列旁、短列**框外**的页面空白不可落」—— 列高不齐与「完全任意位置可落」在几何上互斥，用户已就本权衡明确裁决取前者。
- **档 A（`align-items: stretch` 各列等高）已由用户否决，不实现**。

**B3′ 高亮单点 = 既有 `.kcol.dragover`（规则本体零改动）**

- `outline: 2px dashed #5b86a8; outline-offset: -2px`（`1531`）已画在列的 border box 上，不被列自身 `overflow-y:auto` 裁掉；列被拉高后虚线自动覆盖含卡片区整框。
- 真正要做的是 **B1′ 让类落到列上** + 新增**负锚**禁止 `.kcard.dragover` 出现（B3′ 唯一执法面）。

**B4′ markup 零改**：`views.ts` 不加列内包装层、不删卡片 `data-version` / `draggable` / `data-feature`（三属性 = 闸锁双条件与 drop 同版早退的**承重件**）。打挂证据：`schedule-page.test.mjs:177/848` slice 边界、`:450` 钉 `data-version="">\s*<h3>需求池` 紧邻、`pool-terminal-filter-req04.test.mjs:97` 前视断言串列、live 换块 children 语义、`views.ts:2356` 容器不可替换钉。

**B5′ 写面 / 闸锁零改**：提交唯一通路仍 `POST /features/:id/schedule` + `URLSearchParams({version})`（`780-784`），无 JS 回退 = 详情页表单同路由同 kind；服务端 `board_schedule_state_locked` 与 `deriveScheduleGateOpen` 双条件闸（闸锁卡不渲 `draggable` ⇒ 拖不动）不动。**B1′/B2′ 只放大「往哪儿落」，不放大「谁能落」**。
