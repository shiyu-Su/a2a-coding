**Step 0 核实**: 完成（board `inquiry` `3833c145` **满窗零输出** ⇒ 同会话收窄重派 `246a69a0` 完成；**产品经理职责位**；只读零改动）

## 要解决什么问题

- **当前行为**：依赖图**按 project 分管道**，每管道一枚独立 `<details class="pipe">` + **一枚独立 SVG 画布**（`graph-view.ts:1125` details / `:1129-1130` grid+svg）。管道之间不共画布 ⇒ **跨管道的依赖边画不出来** —— `routeIntraEdges` 对不在本 grid 的端点直接 `continue`（`:817-819`），只能用 `⇠#k` 角标（`renderDepMarks:1048`，数据 `crossIn:1176-1187`）+ 底部边清单表达，**看不出从哪到哪**。实例：`eb86d5e8`（28 任务 / 3 管道）里 board↔orch↔flow 有多条跨管道边。
- **期望行为**：**合并为一张画布**，各管道以**几何框**呈现，跨管道边**画成真连线**，并与同管道边**同受既有三条硬判据**（① 端点落节点边框线中点；② 连线不重叠；③ 连线不穿节点）。

> **确认点**：本节确认的是问题，不是方案。

## 关键核实结论（board `246a69a0`）

1. **现状落点**：渲染链 `renderDependencyGraphSection`（`:1156`）→ 号序/管道/层号（`:1169-1171`）→ `pipelines.map(renderPipeline)`（`:1217`）；`renderPipeline`（`:1110`）逐管道产 details + 一枚 `.dg-grid` + 恰一枚 `<svg class="dg-links">`（`renderPipeSvg:1073`）。`⇠+m`（`:1054`）= 超 `MAX_DEP_MARKS=3`（`:1017`）的折叠隐藏枚数。
2. **可行性 = 可行**（纯 SSR 几何 + 渲染层改造）：**不改任何 `DG_*` 常量数值**；需**新增** —— ① 框级常量族 `DG_FRAME_*`（框内边距 / 框间间距）② 一枚 **canvas 级布局函数**（逐框偏移 = 框 bbox + 框间距；bbox 可由现有 cells 推出，**无需新数据源**）③ **跨框走线档**（第三种 `kind`）。另：`DG_PAD_R=96`（`:523`，为角标越界预留）在角标退役后**语义悬空** ⇒ 须重定或摘除。
3. **坐标底座**：**形状已有、坐标系没有** —— 分组信息在外层 `GraphPipeline{projectId,nodes}`（`:367-371`），但 `pipeGridLayout` 出参全是**管道内局部坐标**（`colX[0]=DG_PAD_L:644` / `rowY[0]=DG_PAD_T:652`），`PipeGridCell`（`:534-552`）**不带 projectId / 框偏移**，`width/height` 也逐管道（`:698-699`）。
4. **列语义**：**框内列**（保留 `compressPipeLayers:476` 逐管道密列）是**唯一不动 I1–I4 陈述**的选项；**全局列**会破两处 —— I4 的 `width` 公式（`:698`）与「每列非空」密列性质（`:471-473`），且框内出现跨管道空列。**代价**：跨管道边的 `colSpan` 判档（`:823`）失去意义 ⇒ 须用新跨框档；**I1/I3 陈述不变、论域扩大到全画布 cells ⇒ 判据变严，可能出现新增红**。
5. **`.pipe` 豁免归属（关键结论）**：免手刷跳拍判据 `.pipe` 是唯一豁免类，而**豁免跟类名走、不跟 details 语义走** ⇒ **合并后的单画布容器必须仍叫 `.pipe`**（管道框退化为画布内的几何框、**不再是 details**）。不改判据也不保留 `.pipe` ⇒ `holdAnchor` 每拍恒真 ⇒ graph 锚**永久冻结**（正是当年加豁免要修的形态）；改判据字面则翻两条逐字正则钉。
6. **顺序**：本卡排 **`9b51af16`（原 `b31c6d7e`，编号口径）之后** —— 它改的 `taskOrdinalMap` 正是本卡 chip / 框标签 / 退役角标的取数面；`eb86d5e8` 的 board 九枚落 `derive / views / version-order / requirement / relay / heartbeat / fixture`、**不触 `graph-view.ts`**，只同 `views.ts`/`web.test.mjs` 不同区 ⇒ 顺序依赖、非重复改造。
7. **量级**：`graph-view.ts` 约 **200–350 行**改写/新增 + `layout.ts` CSS 约 **15–30 行**（`.pipe`/`.pipe-body`/`.dg-grid` 一族 `:1459-1484`，横滚职责从逐管道 `.pipe-body:1462` 上抬到画布）；测试约 **200–400 行**（`graph-view.test.mjs` 的「每管道恰一枚 svg/grid/pipe-body」枚数族与逐 `pipe-body` 分席坐标锚全部要重指向）。**零新增内联脚本**（八元闭集不扩）。
8. **技术可行性假设（已核实成立）**：合并后几何仍可在 **SSR 侧一次算完**、以 `left/top` + 单枚 `inset:0` SVG 表达（现状即此形态；`renderPipeSvg:1073` 不写 `viewBox` ⇒ 用户单位 = CSS px 1:1）。**不需引入脚本算布局、不需新栈**。⇒ 风险**不在可行性**，而在第 4 条的**论域扩大后 I1 是否仍可满足**；若跨框边不可避免穿他框 chip，出路只有「跨框边一律走**框外公共通道带**」，属可执行。
9. **顺带登记的既有滞后**：`layout.ts:1017` 注释把 pipe 落点写成 `graph-view.ts:471`，实际在 `:1110` —— 本卡开工时一并重锚。
