## 关键核实结论（board 产品经理 `3e442f37`）

1. **件一根因（单点，主因）**：`crossPath`（`src/graph-view.ts:1160`）第一枚弧的三枚控制点 **y 全 = `y0`** ⇒ 曲线**在源行高度上贴行扫完几乎整段水平距离**，只在末端抬 `k1`（`arcK = max(6, min(34, dx/3))` **只限手柄长、不限横扫跨度**）。触发条件 = `routeCrossFrameEdges` 的基线选择（`:1245-1246`）：**回流边** `legX = DG_CANVAS_PAD(8)` 而 `x0 ≈ 1179` ⇒ 弧1 退化成 **1171px 贴行横扫**，正对宿主实测（`k1=34` 封顶、`1179−34=1145` 逐字吻合）。**⇒ 设计原文没写错，是实现把「水平段」的第二份（弧1 内的隐式水平跨度）留在了框内。**
2. **件一第二条机制（本版未观测到、结构上存在，须一并进锚）**：末弧只在 `x ∈ [x1−k3, x1]`（≤34px）内完成 `bandY → y1` 的竖距；目标框与源框**跨多框**时，这条 34px 宽竖带要纵穿中间所有框，各框列宽独立 ⇒ 该 x 在中间框里**不保证落在列通道** ⇒ 穿模。实测三条穿模边都是回流（弧1 主导）；**正向跨多框边只是没撞上，不是不会撞**。
3. **存在无穿模的合法走线 ⇒ 定性 = 小修（增补轨），不构成方案变**：合法形 = **五段四转** —— `H(短·源行) → V(源框列通道内·到框间带) → H(带内·到目标框列通道 x) → V(目标框列通道内·到 y1) → H(短·入左缘)`；「长横」全在带内、「长竖」全在列通道或 margin 内，两者**结构上都不碰 chip**。**不改 (A) 选型、不改件三 端点定义式、不加用户可见新行为** ⇒ 小修。**但代价要说清**：跨框边 **3 段 → 5 段**、并新增「**目标侧**通道 / 带选取」一整趟分配 —— **不是调参能解决的**；若坚持「保持 3 段原语只改参数」，则**属方案变**（须回 Step 0 重裁选型）。
4. **件二根因（三问）**：① **gutter 容量无校验（真缺陷）** —— `DG_CANVAS_GUTTER = 24` 而 lane 步长 14 ⇒ 左 margin 只容 λ=0,1（x=8,22）；λ=2 → x=36、λ=3 → x=50 **已落进框内**（框从 `dx=24` 起）⇒ 回流腿从「画布通道」**漂移成框内腿**，且**无任何不等式钉住**。② **两处 y 口径不一致（真缺陷、量级小）** —— 装箱输入用 `bandBaseY`（带中线 `:1304`），实际 `yb = bandLanes[band][0] + busLane·12`（`:1321-1324`）⇒ `laneCount>1` 时脱钩，最多差 ≈12–24px。③ **主叠因与件一同源** —— 共享源点 / 同行的回流边，弧1 在同一条 `y0` 上共线横扫同一段 x；装箱只把腿口挪开 14px，**整段 y0 横扫逐字重合** ⇒ 这正是 `#29–#30` 共 62 段的量级来源。**⇒ 件一的修复顺手消掉件二的主叠因。**
5. **分道该落哪（board 立场）**：长横的分道键归**带内 lane**（`busLane`·`DG_BUS_PITCH`），长竖的分道键归**画布 gutter / 列通道 lane**（`λ`·`DG_LANE_PITCH`）；`DG_CROSS_MIN` 只管带高下界、与分席无关。**须新增一枚 gutter lane 容量上界**（由 `DG_CANVAS_GUTTER − DG_CANVAS_PAD` 与 `DG_LANE_PITCH` 推，超出即换带 / 换 margin，而不是继续 +14 往框里挤）；带高预算与回流 lane 数须**同源回灌**。
6. **框内边共段须分桶再定性**：G5 口径已钉（共端点不算重叠、共段才算、孤立交点允许，执行半径 `G5_END_EXEMPT_PX = 24`）⇒ 重测时**按「叠点是否落在两共用端点 24px 半径内」分桶**：同目标汇聚于同一入点的末段近共线属**合法汇聚**（应剔除），**超出该半径的共段才是真叠线**。现有 18 对的两桶占比待重测数据回答。
7. **为何 I1/G4 离线锚全绿却真机穿模（作用域缺口四处）**：① **夹具面** —— G4 三夹具全是**单 project** ⇒ `crossEdges` 结构上恒空 ⇒ `routeCrossFrameEdges` / `crossPath` 的 path **从未进过任何几何判据**；② **障碍集面** —— `findPenetrations(routes, grid)` 的障碍 = **一枚 grid 的 cells**，没有「其余框的 chip 并集」；③ **坐标系面** —— G4 吃**未平移**的框内网格，跨框边走**画布坐标**，画布面上只有端点锚、**不含穿模判据**；④ **判据形态本身够用** —— 弧1 的段 bbox 与中间框 chip 行严格交叠，**现有度量法若能拿到画布障碍集就会判红**。**缺口不在精度、只在作用域。**
8. **一个反向陷阱（须登记）**：五段修复形的末弧 bbox 是「34 宽 × 数百高」的**保守盒**，会盖到大片合法空白 ⇒ **直接把 I1 的 bbox 判据搬到画布级会把正确形态也判红**；新锚须改用**采样点 × 矩形**的精确判据。
9. **件三（硬约束）现状**：连线两端 —— 上一枚增补 `a0682281` 的 n7 已真机验证「全部 68 边 / 136 点、配对 100% 为 源 `rightMid` → 目标 `leftMid`、偏差恒 (0,0)」⇒ **当前成立**；本件要求**修复后仍成立**（作为验收判据）。
10. **共同落点与量级**：`crossPath`（`:1141-1166`）3 段 → 5 段；`routeCrossFrameEdges`（`:1245-1247`、`:1295-1326`）新增目标侧选取 + gutter 容量校验 + y 口径统一。`crossPath` ≈ 40–60 行、router ≈ 60–100 行、**锚 ≈ 150–250 行**（画布级障碍集 + 精确穿模判据 + gutter 容量钉 + 回流分席钉）⇒ **估 5–7 枚 DAG 节点**。**风险登记**：本版是「模型侧锚全绿 / 真板穿模」的**第二次同型事故** ⇒ board 建议**先补锚、再改算法**（锚先落成反例常驻形态，照 `G4-穿节点④` 先例）。

12. **锚账（须新增，缺一不可）**：① **画布级 I1′**（障碍集 = 各框 `shiftPipeGrid` 后 chip 盒并集，含除本边两端所在框外的全部框；判据 = **采样点** ∩ 非端 chip 内部 = ∅）；② **夹具必须多 project 且含回流**（回流跨 2 框 / 跨 3 框 / **正向跨多框** / 同源出 2–3 条回流边四形）；③ **常驻反例**（把长横「抬回源行高度」必被抓住；修复形零穿模 —— 两头不许空转）；④ **回流分席锚**（同 gutter 内各腿 `legX` 两两不同 **且 ≤ `DG_CANVAS_GUTTER` 上界**；兜底面复用 G5 采样叠点法作用在画布路径上、显式豁免共用端点 24px）。**另须一枚「复现锚」**：真板 `eb86d5e8` 的 path 集合 vs 夹具离线跑出的**逐字相等** —— 否则「离线绿」与「真板对」之间仍断链，同型事故会第三次发生。
