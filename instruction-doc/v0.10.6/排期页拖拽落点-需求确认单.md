## 要解决什么问题

> 问题域描述；本节确认点 =「我理解你要解决的是不是这个问题」——确认的是问题，不是方案。

- **当前行为**：排期页把需求卡片拖入某版本框时，**版本框内只有部分区域能放入** ——
  - 版本框（SWIM 列 `.kcol`）**只到自身内容那么高**，短列 / 空列下方那一大片「看着是这一版栏位」的空白**实际不属于该框**，指针落在那里 → 落点判定返回 `null` → **放不进**；
  - 指针**压在卡片上**拖动时，目标版本框的虚线高亮**整块消失**（只在列头、卡间窄缝里闪一下），用户按高亮判断，观感上等同于「这里放不进去」（功能上其实放得成）。
  - **用户实测补充（2026-10-13）**：「我测试的时候，被拖动卡片只有和版本列的标题处重叠时 才显示外部的虚线框」—— 与根因②吻合（虚线框仅在鼠标命中列本身时画出）。
- **期望行为**：**只要指针落在目标版本框的可见范围内（列头 / 卡片上 / 框内空白 / 空框），即可放入**；拖动时目标框有**持续、清晰**的落点高亮。

**不做（本需求边界，待用户确认）**：不改数据面 / 引擎 / 协议；不改排期写锁 / 已发版锁 / 归属语义；**不做「落到框内指定位置（手工排卡序）」**（见待裁 ③）。

## 关键核实结论（board `8c04e564`，只读）

> 「当前行为 / 影响范围（粗判）/ 技术可行性假设」由执行单元核实，orch 不得单方断言。

1. **落点判定的实际绑定**：全部为 **document 级事件委托**，命中函数 `colOf`（`board/src/web/layout.ts:758-765`）从 `e.target` 上溯，取**第一个带 `data-version` 属性的祖先（含自身）**为落点，边界 `#schedule-board`。版本框 markup = `<div class="kcol" data-version="X">`（`views.ts:2347-2350`），**无独立卡片列表子容器**。
2. **根因①（几何，真·放不进）**：`.kanban { align-items: flex-start }`（`layout.ts:1501`）使每个 `.kcol` 只到内容高度；`#schedule-board > .kcol { max-height: … }`（`layout.ts:1510`）**只给上限、无 `min-height`** ⇒ 短列 / 空列（`views.ts:2141` 占位空列仅约列头高）下方空白不属于框内。**同仓先例**：管理页两栏拖拽的 `.mcol` 有 `min-height: 84px`（`layout.ts:1536`）⇒ 整框接收；排期页缺此条。
3. **根因②（高亮失效，感知放大器）**：`colOf` 只认 `data-version`，而**卡片自己也带 `data-version`**（`views.ts:2174`）⇒ 指针在卡上时命中**卡片**，`.dragover` 加在 `.kcard` 上；而 CSS **只定义了 `.kcol.dragover`**（`layout.ts:1531`），`.kcard.dragover` 无规则；又因进入子元素触发父级 `dragleave`（`layout.ts:811-814`）⇒ 压在卡上时整列高亮消失。此路径**功能上能落成**（卡片 `data-version` 与所在列同源同值），故属**可见性缺陷**。
4. **影响范围粗判**：源文件**预计仅 1 枚** `board/src/web/layout.ts`（CSS 锁 `#schedule-board` 作用域 + `colOf` 判据）；**`views.ts` 建议零改动**（列内不加包装层 —— 会打断 `schedule-page.test.mjs:177/848` 的 slice 边界、`views.ts:2356` 容器不可替换钉、live 换块 children 语义）。测试锚：`n3-regression-anchors.test.mjs:454-471`、`schedule-page.test.mjs:442-451`、`live-refresh.test.mjs:466`；**无既有 CSS 内容断言**（纯 CSS 改动需新增锚）。**根回归影响面预计零**（不新增文件、不改 exports）。
5. **技术可行性假设（已核实成立）**：把落点接受面扩到整个版本框、**只动体验层**（CSS 拉伸 + `colOf` 只认列），**服务端写面与闸锁零改动**（提交仍 `POST /features/:id/schedule`、载荷仅 `version`）。反例逐条核（误落它框 / 闸锁态 / 空框 / 无折叠 / 高亮改 `colOf` 的语义等价 / 与免手刷交互）**均不构成阻断**；唯一副作用 = 误投锁列 / released 列的 **409 弹卡概率上升**（既有可见路径）。
6. **不可行形态（已排除）**：给列加内层包装 `<div class="kcol-body">` 或把 `data-version` 挪到内层 —— 会同时打断测试 slice 边界与 live 换块语义。
7. **体量预估**：src **~2–6 行**（`colOf` 1–3 行 + CSS 2–3 行）；board 测试 **~10–25 行**；根回归 0；**真机验收必做一次**（板测试无 jsdom，离线断言覆盖不到几何）⇒ 属「未覆盖验证项」，验收须显式列出。
8. **语义澄清**：用户抱怨的是「**落点接受面太窄**」，**不是**「插入位置固定」—— 拖拽提交载荷**只有 `version`**（`layout.ts:782`，n3 负锚 `doesNotMatch /stage|approval/`），「落到框内第几个位置」**当前无可写通道**；且列内序是**派生序**（`version-order.compareFeatureCard`，v0.10.4 落地，状态一变即跨档跳位）。

## 成功标准（用户语言）

1. 排期页，把需求卡拖到某版本框的**任意可见位置**（列头 / 卡片上 / 框内空白 / 空框内）**都能放入**；
2. 拖动经过目标版本框时，**整框有持续清晰的高亮**（不再在卡上消失）；
3. 空列 / 短列下方仍属于该版本框，**拖到框的可见下沿也能放入**；
4. 未破坏既有行为：闸锁卡仍拖不起、锁定态 / 已发版列仍由服务端 409 拦、免手刷（就地换块 + 拖拽中跳拍）不受影响。
