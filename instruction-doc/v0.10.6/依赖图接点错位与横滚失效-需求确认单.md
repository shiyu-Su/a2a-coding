## 要解决什么问题

- **当前行为**：主需求 `4bb23554`「依赖图合并单画布」交付版（载体 board `0.12.1` 在跑）首次看板面暴露两处：
  1. **件一 · 连线两端接点错位** —— 依赖图每条边的**两端**都没落在节点边框线的右 / 左缘中点上。宿真实测（真板 `:3400` · `eb86d5e8` 页 · 画布坐标系）：端点落 `(cell.left + 65, cell.top + 7)`，而应在 `(cell.left + 74, cell.top + 28)` ⇒ **系统偏 (−9, −21)，源端与目标端同偏**（整张图整体错位、非个别边）。**这是 v0.10.5 增补 `d69f494d`「件一 接点对齐」已验收判据的回归。**
  2. **件二 · 框宽溢出且无横向滚动** —— 图宽超出其外侧容器，且**只能推整个页面**横滚，图区自己没有左右滚动条。
- **期望行为**：① 连线两端精确接在节点方框的右 / 左缘中点（±1px）；② 图超出容器宽时**在图区就地左右滚动**（滚动条出现在图区），不动整页。

> **确认点**：本节确认的是问题，不是方案。

## 关键核实结论（board 产品经理 `1232d6fd`）

1. **件一根因（唯一一处）**：`graph-view.ts:1564` 的 `shiftPipeGrid(grid, frame.dx, frame.dy)` —— `frame.dx/dy` 是**框外缘**左上角（`:790-796` 注释与 `:1609` inline `left/top` 均为外缘口径），但网格原点在 DOM 上**不是**框外缘：`.dg-canvas .pipe-body`（`layout.ts:1487`）是绝对定位，其 containing block = `.pipe` 的 **padding box** ⇒ 真实网格原点 = 外缘 **+ border + pad**（x）/ **+ border + title**（y）。数值逐字吻合宿主实测：`DG_FRAME_BORDER(1) + DG_FRAME_PAD(8) = 9`、`DG_FRAME_BORDER(1) + DG_FRAME_TITLE_H(20) = 21`。
2. **不是 `crossPath` / `routeIntraEdges` 的锅**：二者只消费传入网格的 `chipRight/chipMidY/chipX`，入参错则全错、本身算得对；框内边与跨框边**同源** ⇒ 一处改完两类边。
3. **改法推荐 = 改模型**（新增两枚派生常量 `DG_GRID_ORIGIN_X = border+pad` / `DG_GRID_ORIGIN_Y = border+title`，供 `:1564` 与测试**同一源**取用），**不改渲染拉平** —— 后者要在 CSS 里造第二份偏移 = 把本版刚裁掉的「双事实源」缺陷换个形式请回来；且 `canvasLayout` 的 `frameW/frameH`（`:871-872`）**本就已含**这套内缘，改模型是把不一致处拉回既有口径。
4. **⚠ 件一② 这枚锚与实现「同错」**：`test/graph-view.test.mjs:1640-1641` 与 `:2818-2822` 的换算式都拿**框外缘 origin** 加偏（正是模型漏掉的那层）⇒ **现网 `node --test test/graph-view.test.mjs` 84/84 全绿，却是「锚通过 + 线上错位」同时成立**。修复须把两式各加 `DG_GRID_ORIGIN_X/Y`，并把 `:1648-1655` 的反向钉从「未加偏不得命中」**扩成两形**（未加偏 ∧ 只加 dx/dy 不加框内缘 —— 都不得命中），后者才是本次回归的机械凭据。
5. **件二根因 = §2.2.2 那一行的方案落点本身写错**（**不是实现走样**）：`.dg-canvas` 同时是**滚动容器**（`overflow-x:auto`）与被内容定宽的元素（inline `width:${layout.width}px`，`:1628/:1631`）⇒ 内容永不溢出自己 ⇒ `overflow-x:auto` **恒 inert**；溢出逃到 `.dep-graph`（该类在 `layout.ts` 里**一条规则都没有**、`overflow-x` 缺省 `visible`）⇒ 由整页 / 浮层承接。
6. **件二落点推荐 = A（外层 `.dep-graph{overflow-x:auto}`）**：合法判据两条 —— ① 滚动容器宽度必须**受外部约束**（不得被内容定宽）；② 必须是坐标系承载者 `.dg-canvas` 的**祖先**。A 满足两条且 `.dg-canvas` 原样不动（保住 `position:relative` + inline W/H 这枚画布坐标系）；改动 = CSS 新建一条 + 摘掉 `.dg-canvas` 的 `overflow-x:auto`。**且 doc §2.2.2 原行本就写着「外层 `.dep-graph` 承接外距」** ⇒ 本改法是把该行后半句的落点**纠正到它自己已指定的元素**，不是新增第三种形态。B（新增 wrapper）要翻一串结构锚、且违「不新增框级元素类」已裁；C（每框各自横滚）**几何上不可能**（S1 下 svg 与框是兄弟 ⇒ 线不跟 chip 走）。
7. **必须留在**外缘**口径、不得顺手加偏的点**：`bandLanes` / `firstLaneY`（`:890`）与框间带中线（`:1333-1335`）—— 它们描述框矩形**之间**的带、不是框内内容。
8. **影响范围（粗判）**：只触达 board 单单元（`graph-view.ts` 1 处入参 + 2 枚常量 + 注释 · `layout.ts` 1 条规则迁移 + 2 处注释 · `test/graph-view.test.mjs` 约 5 处锚）；**flow / orch / machine 零触达、协议零改动、无同升**。文档只动主需求那一份改造文档（「增补」节 +1 版 + §2.2.2 行订正）。量级：件一 graph-view ≈6–10 行 / 测试 ≈15–25 行；件二 CSS 2–3 行 / 测试 8–15 行。
9. **同源第三处（叙述性成因）**：注释面「框内 origin = border + title + pad」只写在 CSS 侧（`layout.ts:1485-1486`），模型侧 `shiftPipeGrid` 的 doc（`:743-748`）完全没提这层内缘 ⇒ 须同批补上。未发现第三处真实代码病灶。
10. **两件不能一处改完**（共同点只在抽象层：都是「模型 ↔ 渲染 ↔ CSS 三层之间少了一层换算」），但**可同增补内两节点**做。
11. **离线锚对这两条都无覆盖**（件一② 与实现同错；件二 的正钉只验声明在场、不验能否真溢出）⇒ **验收必须补真板 `:3400` DOM 实测**（端点 === `.dg-chip` 边框线中点 ±1px；`.dep-graph` `scrollWidth > clientWidth` 且滚条出现在图区），**不得只以离线断言放行**。
