# board 配置说明

本文件承接 [`board/README.md`](../README.md) 的配置语义

## 配置文件

| 配置文件 | 说明 |
| - | - |
| [config.json](config.json) | 实际被读取的配置文件，配置值覆盖配置项默认值 |
| [config.json.default](config.json.default) | 用于记录配置项默认值 |
| [config.json.example](config.json.example) | 配置内容示例，首次使用可复制为同目录下`config.json` |

- 配置文件路径由环境变量 `BOARD_CONFIG` 覆盖（只覆盖路径，不承载配置内容；argv 与其余 env 的配置内容通道已撤掉）。
- 两份模板均不参与加载、无自动复制回退；`_` 前缀键 = 注释，加载器忽略，说明位 = 本文件。
- 启动期读一次 ⇒ 改配置须重启板进程；非法值以 `[config] <字段路径> … —— 对策：…` 报错拒起，不静默降级。

## 配置项

| 配置项 | 默认值 | 配置说明 |
| - | - | - |
| port | 3400 | 板服务端口。不填 / 空值 = 用缺省。非 1–65535 整数 ⇒ 拒绝启动。 |
| host | 127.0.0.1 | 板服务绑定地址，可覆盖为 `::1` / `localhost`。**非 loopback 一律拒起**；远程访问请在板前挂反向代理做鉴权。 |
| orgsDir | - | 项目组目录根。**根必须预先存在**（缺失 ⇒ 启动 warn + 触发期 503，板不代建）。板上创建项目组，自动创建`{orgsDir}/{projectGroup}`。留空 / 缺键 = 未配置 ⇒ 宿主面不装配（宿主写端点 503 `host_face_disabled`），板照常起。 |
| group | 空串（= 未配置） | 板级默认组织，可选：仅当提需求表单留空时兜底。空串 / 纯空白 = 未配置，不是错误（表单组织名变为必填）；表单留空且无此默认 ⇒ 400 `board_group_required`。绝不猜组名。 |
| hostKind | claude | 板默认拉起作为宿主Agent的类型，当前仅支持：claude、opencode、codex、qoder-cn |
| hostModel | 空串（不透传） | 起桥时原样透传给后端，板不校验。未配置 ⇒ 不透传，由后端缺省决定。仅对新建桥生效，改动须重启板进程。非字符串 ⇒ 拒绝启动。 |
| bridgeUrl | http://127.0.0.1:3300 | orch-bridge读地址 |
| mcpBaseUrl | http://127.0.0.1:8787 | orch-bridge-mcp基地址，项目组创建后拼接 `/{项目组名}/mcp` 于 mcpBaseURL 后。 |
| machineDist | `<仓根>/machine/dist`（推导） | machine 构建产物目录，板 spawn 宿主Agent所需。|
| repoRoot | 板根上一级（推导） | 读文档面主仓根。源 A = `<repoRoot>/doc/{Group Version}/`，源 B = `<orgsDir>/<组织>/doc/{Group Version}/`。目录不存在不是错误（按 `not_found` 降级）。非法类型 ⇒ 拒绝启动。 |
| turnTimeoutMs | 不配置（交下游 600000 = 10 min） | 宿主对话单轮有界等待（毫秒）。非正整数 ⇒ 拒绝启动。到点落 `timeout` 终态。 |

## 已退役键

- `releasedVersions`：运行时版本锁改读版本台账（`.data/versions.json` 的 `status=released`），本键不进入 `BoardConfig`；历史键只供启动期一次性迁移（config → 台账），非法形态仍 fail-fast（防已发版锁静默消失）。

## 不同 Agent 的配置方式（全局面 vs 组织面）

同一块板可以给不同组织挂不同的后端 agent，两面的键各配各的、不是成对的一对：

| 面 | 落点 | 键 | 生效时机 |
|---|---|---|---|
| **全局面** | `config/config.json`（活配置） | `hostKind` / `hostModel` | 启动期读一次 ⇒ 改动须重启板进程 |
| **组织面** | `.data/orgs.json`（板侧组织台账，经 `POST /orgs` 的 `action=setHostAgent` 分支写两键） | `agentKind` / `agentModel`（`null` = 该键未配） | 每次建桥现读台账 ⇒ 改动免重启（仍只影响新建桥） |

- **`hostKind`（全局面）**：仅作新建桥的缺省 kind；`kind → 后端命令` 的映射归 machine 侧 `getAdapter()`，板不自拼 argv。组织级配了 `agentKind` 即以组织面为准。
- **`hostModel`（全局面）**：起桥时经 `agentConfig` 原样透传给后端（machine 侧适配器解析），板不校验取值；缺省 / 空串 = 不透传，模型由后端自身缺省决定。仅对新建桥生效，改动须重启板进程。
- **回落各自独立**：`agentKind` 只回落 `hostKind`、`agentModel` 只回落 `hostModel`，两键分别判定（`host-face.ts` 的 `orgBridgeConfig` 是唯一落点）。
- **唯一跨键判据**：组织配了 `agentKind` 而未配 `agentModel` ⇒ 不沿用全局 `hostModel`（全局 model 按全局 kind 的命名空间配置，塞给别的适配器必错）；该桥不带 model 起，由该 kind 的后端自身缺省接管。
- **换 model / 提示词 / 档位**：同一 `agentKind` 内才能换；组织面一改 `agentKind` 即等于换后端适配器，旧 kind 的 model 名不迁移。
- **`roles`** 不在板侧配置，其配置面与语义归 machine，见 [`machine/config/配置说明.md`](../../machine/config/配置说明.md)。
- **kind 取值清单**不在此枚举，清单源 = 仓库根 `PROTOCOL.md` 的 `agent-kinds` 锚点；拿到不被 `getAdapter()` 认识的 kind 时在起桥期报错。
