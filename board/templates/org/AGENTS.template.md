## 2. MCP 与连接身份 —— 由板注入，勿手改

- 本组织编排会话的 a2a MCP 端点形如 `http://<编排桥地址>:8787/{ORG_NAME}/mcp`，**由板（或 V1 阶段的宿主配置维护者）注入宿主的 MCP 配置**。
- **本文件不含 MCP 配置，也不得写入**：MCP 端点写进这里 = 第二份真相（注入面改了就对不上）。要核对连接身份，看板上的组织详情，或宿主会话里已注册的 MCP 条目。
- **URL 首段就是身份**：漏写组名段（`/mcp`）会被 403 拒；写成别的组名会以别的组身份工作（视野与归属校验全变）。
- **组 ≠ 安全边界**：MCP 端点零鉴权，组名段只界定可见性与派发范围。不要把本目录当权限隔离手段。

## 4. 等待纪律（派发后必须用脚本阻塞等待）

本目录 `scripts/` 内自带两个只读等待脚本（**缺省打编排桥的只读工作台 `http://127.0.0.1:3300` ⇒ 该端口须保持可用**；可用 `--base <url>` 或环境变量 `WATCH_BASE_URL` 覆盖）：

- **过审放行 Feature 后**：`node scripts/watch-feature.mjs <featureId>`
  退出码分流：`0` 已离开 `executing`（完成侧）· `10` 失败收敛静止 · `11` `needs_input` · `12` `cancelled` · `13` `failed`（仅 DAG 非法）· `20` 窗口耗尽 · `1` 脚本错误。
- **派发常规 `a2a_call` 任务后**：`node scripts/watch-task.mjs <taskId...>`（**入参必须是 `a2a_call` 返回的本地 taskId**，传节点的 `remoteTaskId` 会 404）
  退出码三档：`0` **等到了**（`failed` / `blocked` 也退 0 ⇒ **0 ≠ 成功**，成败看 stdout 状态行）· `20` 窗口耗尽 · `1` 脚本错误。

**三条硬纪律**：

1. **禁止**用 `a2a_task_status` / `a2a_tasks` 手工轮询来等待 —— 等待交给脚本，脚本只读、可重复调用。
2. 脚本**只打印状态**；需要详情（失败原因 / 待裁决问题 / 结果全文）时，**自行调用一次** MCP 工具取，不要循环取。
3. 默认窗口 `--interval 10000 × --max 180`（30 min）可能超过单次工具调用上限：未结束时**再调用同一条命令**即可。

| `planlog.md` | 编排 agent | 顶部版本待办（需求 + REQ-ID + **当前步骤** + 状态）；非影响性改进点一句话登记，不展开 |
| `CHANGELOG.md` | 编排 agent | **只在发版流程中写**；需求进行中不动它 |
| `.a2a/` | 编排桥（运行时自动） | 会话映射；建议 gitignore |

`stage` / `version` / `approval` 的**唯一事实源在引擎**：文档与 planlog 都不得另存一份字段值，只写「下一步做什么」与「确认内容」。
